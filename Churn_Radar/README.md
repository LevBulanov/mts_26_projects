# ChurnRadar

Модель прогнозирует отток абонентов телеком-оператора по данным о платежах, трафике, звонках и тарифах. Бинарный прогноз можно использовать для отбора клиентов, с которыми свяжется команда удержания.

[Ноутбук](churn_radar.ipynb) · [HTML-отчёт с графиками](churn_radar.html)

## Результаты

| Метрика | Значение |
| --- | --- |
| OOF ROC-AUC | 0,9030 |
| OOF F1 | 0,6518 |
| Порог классификации | 0,3501 |
| Test F1 | **0,6498** |
| Задержка p50 / p95 / p99 | **0,025 / 0,037 / 0,051 мс** |

Задержка измерена на Windows 11 x64 на 20 000 запросах после прогрева. Замер включает преобразование записи и предсказание, модель работает на одном потоке. Целевой ориентир p99 — 0,1 мс.

Классы одиночного скоринга совпали с пакетным прогнозом на всех 497 586 строках теста. PSI превысил порог в 342 из 995 полных окон. Наибольший средний сдвиг наблюдался у `зона_1` и `зона_2`.

## Что внутри

- **Признаки.** Флаги пропусков, разбор текстового поля `pack`, восстановление обфусцированных счётчиков и признаки активности, например средний чек и отношение трафика к звонкам.
- **Модель.** LightGBM с 100 деревьями. В каждом из пяти стратифицированных фолдов категориальный кодировщик обучается на своей обучающей части. Порог выбирается по OOF, F1 проверяется на отдельном тесте.
- **Скоринг.** `get_score(record)` принимает словарь с одной записью и возвращает `client_id` и `prediction` (0 или 1). Табличная предобработка вынесена из пути запроса. Для предсказания используется скомпилированная модель `lleaves` с одним потоком.
- **Мониторинг.** На окнах из 500 записей считаются PSI, доля неизвестных категорий и доля прогнозов оттока. Для числовых признаков с повышенным PSI дополнительно рассчитывается KS-статистика.

## Запуск в Windows

Нужен Python 3.12. Эти команды рассчитаны на запуск из корня репозитория в PowerShell.

```powershell
Set-Location Churn_Radar
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyterlab churn_radar.ipynb
```

Выберите ядро Python из окружения и выполните **Run All Cells**. Следующие команды выполняют ноутбук без интерфейса и обновляют HTML.

```powershell
.\.venv\Scripts\python.exe -m nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=900 churn_radar.ipynb
.\.venv\Scripts\python.exe -m nbconvert --to html churn_radar.ipynb
```

## Данные

Положите `train.csv` и `test_full.csv` рядом с ноутбуком. CSV-файлы обфусцированы и хранятся локально.

| Поля | Содержание |
| --- | --- |
| `client_id`, `binary_target` | Идентификатор клиента и метка оттока |
| `регион`, `использование`, `mrg_` | Регион, стаж использования, служебный флаг |
| `сумма`, `частота_пополнения`, `доход`, `сегмент_arpu`, `частота` | Платежи и выручка |
| `объем_данных`, `on_net`, `зона_1`, `зона_2` | Трафик и звонки |
| `продукт_1`, `продукт_2`, `pack`, `pack_freq` | Тарифы, активный пакет и частота его активации |
| `секретный_скор` | Скор из исходных данных |

В секции скоринга есть пример вызова с пропуском и ранее неизвестной категорией. В секции мониторинга весь тест воспроизводится как поток одиночных запросов и сверяется с пакетными предсказаниями.
